## 2. 演示32个设备同时接入

终端A：

```sh
cd /home/book/batt-access

```

如果上一轮服务还在运行，先在原终端Ctrl+C退出，再启动新版。ready应显示milestone=2、max_clients=128、persistence=memory_only。

终端B（另开一个连接同一Ubuntu的SSH窗口）：

```sh

```

预期：

- B先显示 `all_connected`、devices=32，说明32条连接已建立并登录，同时保持在线。
- B随后显示BT000到BT031各一条device_complete。
- B最后显示 `demo_complete`、devices=32、acks=256（每台8个应答）。

模拟器结束后连接会关闭，A继续监听并记录设备offline。程序当前只在内存保留设备档案和告警，未引入数据库。

## 3. 演示同一设备重新登录

保持A的服务运行，在B执行：

```sh
cd /home/book/batt-access
./build/batt-sim --demo relogin
```

模拟器自动完成：

1. BT000旧连接登录、上报52.8V；BT001也独立登录、上报61V。
2. 新连接假冒BT000但devType错误，得到result=0。旧BT000仍能继续上报。
3. 另一条合法BT000连接登录，替换旧连接。旧连接尝试上报99.99V，不应改变当前会话。
4. 新BT000上报65V；同连接重复登录保持原属性；BT001仍可继续上报。

B最终应显示：

```json
{"event":"relogin_complete","old_connection_blocked":true,"other_device_ok":true}
```

A中重点找：

| 日志 | 含义 |
| --- | --- |
| rejected / invalid_login | 无效新登录，没有替换现有合法会话 |
| session_replaced | 同devId的合法新连接替换旧连接；包含两个不同connection_id |
| closed，reason=replaced，was_current=false | 关闭的是已经失效的旧连接，不是刚绑定的新连接 |
| 新连接login，state=connected_no_data | 不把旧连接属性继承为新鲜数据 |
| attributes，BT000电压65V | 新会话的数据有效 |
| BT001仍可更新 | 关闭BT000旧连接没有误伤其他设备 |

不要把登录登记理解为生产级身份认证；这里校验协议字段和连接绑定，不包含企业证书、鉴权或安全上线保证。

## 4. 看一次“连接还在，但数据过期”

生产语义的默认新鲜度仍为90秒。为避免手工演示等待90秒，使用明确标注的测试参数：

先在A按Ctrl+C停止服务，再执行：

```sh
cd /home/book/batt-access
./build/batt-access --test-freshness-ms 3000
```

B执行：

```sh
cd /home/book/batt-access
./build/batt-sim --devices 1 --hold-seconds 5
```

模拟器上报完后保持连接5秒，期间不再更新属性。A应依次出现online_fresh、约3秒后的connected_stale，最后连接关闭后的offline。connected_stale表示数据过期，不能与断线混为一谈。

默认90秒边界和只更新SOC不能刷新旧温度，由可控时钟单测验证；真实TCP场景另以1000ms测试阈值验证连接仍可收发告警。上述3000ms只用于手工演示，不是改了默认业务阈值。

做完后Ctrl+C停掉测试参数服务，下次直接 `./build/batt-access` 即恢复默认90秒。

## 5. 你需要理解的几个点

### 为什么需要connection_id

fd是Linux临时分配的整数，旧连接关闭后会复用。服务每次accept生成新的递增token，并组合本次启动的boot_id作为日志connection_id。epoll事件使用token查表；找不到旧token就丢弃，不按数字fd猜它属于谁。

测试同时覆盖：真实Linux中重复使用同一个fd数字，以及旧会话消息/关闭事件不影响新会话的受控单测。

### 为什么同一个设备要区分连接和档案

- 连接记录属于当前socket，断开就释放接收/发送缓存和fd。
- 设备档案按devId保存当前连接绑定、属性状态和告警历史。
- 新连接生效时，旧token立即失去修改资格；旧关闭通知不能把新会话标offline。
- 告警在同一进程中跨重连保留，避免持续告警每重连一次就变成新事件。新连接属性必须重新采集，避免旧数据冒充新鲜值。

### 当前有没有多线程

还没有工作线程。epoll主线程轮流处理多条连接，属于I/O多路复用；模拟器也不为每个终端建线程。线程分片和查询在下一步C阶段实现。

## 6. 独立运行测试与排错

```sh
cd /home/book/batt-access
./build/core_test
python3 tests/network_test.py ./build/batt-access ./build/batt-sim
```

第一条应显示402 checks passed，第二条应显示Ran 19 tests和OK。网络测试包含真实5秒残帧超时，整体约7秒，耗时会随机器负载变化。

```sh
cd /home/book/batt-access
BATT_BUILD_DIR=build-asan BATT_SANITIZE=ON sh scripts/test-linux.sh
```

bind/listen提示端口占用时，先退出旧服务；不要直接反复启动多个监听19001的服务。Connection refused时，确认A已显示ready、两边业务端口一致。SSH仍使用2222，项目业务仍使用19001。

如果模拟器仍只接入一个设备或ready仍是milestone=1，说明旧进程没有退出或运行的是旧目录，先确认pwd及重新构建。
