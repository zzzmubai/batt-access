# 固定报文与手工预期

机器可读报文：[protocol-samples.json](protocol-samples.json)。这是手工固定样例及预期，最终演示加载它并通过独立Python TCP客户端发送；没有调用C++的Protocol/Sessions/Queries来生成“正确答案”。

| 样例 | 输入与预期 |
| --- | --- |
| login | 110、devType=1、imsi字符串；111关联相同devId/txnNo且result=1；只有登录时为connected_no_data |
| attributes | 电压5280→52.8V、电流-125→-1.25A、SOC80→80%、温度28→28℃；完整合法四项后online_fresh |
| 未使用字段 | 01102001的120.12为未知浮点属性，忽略它，不拒绝整帧 |
| invalid_soc | 同一帧含电压6000与SOC101；整帧拒绝，无ACK，电压仍52.8V、SOC仍80，不能只接纳电压 |
| alarm_open | 01003001、03/1表示当前集合含03；首次建open，重复集合仍只有一条事件 |
| alarm_clear | 同组000/0表示全部恢复；原事件变cleared，历史仍保留；之后03再出现形成新事件 |
| query | 服务发910；911须匹配当前会话、设备和任务编号；完整及时响应success，期限后为timeout，迟到不改终态 |

JSON中的devId=BT000及txnNo是固定示例；演示按连接替换devId、为上报递增txnNo，并使用服务实际分配的query编号。设备上报编号和服务query编号是两条独立序列。响应中的保护参数4150等是模拟数据，不当作真实硬件测量。

告警410发送当前集合，单项消失由下一次完整集合体现；不要构造原协议未使用的“单条03/0恢复”。组缺席不推断恢复，000与活跃项冲突应拒绝。更完整的集合边界由core和network测试覆盖。

C++模拟器仅复用JSON及网络基础辅助函数，未实例化服务端业务状态机；最终演示先单独运行它的32终端生命周期（256次ACK、96条告警历史），再用独立Python客户端控制32条连接完成故障场景。两份脚本/样例不是现场数据证据。
