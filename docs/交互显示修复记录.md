# 交互显示修复（0.3.1）

问题：模拟器每秒上报属性与告警，服务输出大量JSON，status/query结果被刷过去，用户难以观察。

## 修改

- MobaXterm等交互终端默认安静模式，也可用 `./build/batt-access --workers 2 --quiet` 显式开启。
- 隐藏自动属性、告警和重复连接过程日志，正常采集与处理继续进行。
- status显示[STATUS]及中文状态、电压、电流、SOC、温度、worker。
- query显示[QUERY #编号] pending/success/timeout/link_lost的中文含义，成功后[RESULT]显示返回参数；迟到应答显示[LATE]。
- 命令受理时回显 `> status BT000` 等提示，证明输入已送到服务程序。
- 运行时quiet on/off切换；--verbose强制详细JSON。管道模式默认仍为JSON，现有自动化客户端可继续使用。
- ready保留JSON启动信息以便自动化发现监听端口，同时包含quiet字段。

## 用户复现

先在原A/B终端分别Ctrl+C停止旧服务和模拟器。

终端A：

```sh
cd /home/book/batt-access
./build/batt-access --workers 2 --quiet
```

终端B：

```sh
cd /home/book/batt-access
./build/batt-sim --demo serve --devices 1
```

看到B显示serving后，回A输入：

```text
status BT000
query BT000
```

应看到如下类型的行（编号以实际值为准）：

```text
[STATUS] BT000 | online_fresh（在线，数据新鲜） | 电压=52.80V | 电流=-1.25A | SOC=80% | 温度=28C | worker=1
[QUERY #1] BT000 | pending（等待终端应答）
[QUERY #1] BT000 | success（查询成功）
[RESULT #1] {返回的保护参数JSON}
```

status读取当前快照；query发起910查询并展示911返回结果，不会修改电压或SOC。若模拟器仍使用--query-delay-ms 5000，则约3秒会显示timeout、约5秒显示LATE，这是预期的慢应答场景。
