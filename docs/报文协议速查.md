# batt-access 报文协议速查

基于 `src/protocol.hpp`、`src/sim.cpp`、`src/access.cpp` 整理。

所有报文均为 JSON，UTF-8，通过 TCP 19001 收发。

JSON 对象之间无分隔符，接收方用括号配对切分（见 `json_slice.hpp`）。



***

## 一、报文总览



| msgType | 方向       | 含义                       | 对应应答 |
| ------- | -------- | ------------------------ | ---- |
| 110     | 终端 → 服务端 | 登录                       | 111  |
| 111     | 服务端 → 终端 | 登录应答                     | —    |
| 310     | 终端 → 服务端 | 属性上报（电压 / 电流 / SOC / 温度） | 311  |
| 311     | 服务端 → 终端 | 属性应答                     | —    |
| 410     | 终端 → 终端  | 告警快照上报                   | 411  |
| 411     | 服务端 → 终端 | 告警应答                     | —    |
| 910     | 服务端 → 终端 | 下发查询                     | 911  |
| 911     | 终端 → 服务端 | 查询应答                     | —    |

通用信封字段：



* `msgType`：整数，见上表

* `devId`：字符串，非空，长度 ≤ 64

* `txnNo`：整数，>0。请求包自带，应答包原样带回用于关联



***

## 二、终端 → 服务端

### 2.1 登录 110



```
{
  "msgType": 110,
  "devId": "BT000",
  "imsi": "SIM_BT000",
  "txnNo": 1,
  "devType": 1
}
```

字段要求：



* `imsi`：字符串，非空，≤64

* `devType`：必须为整数 `1`，否则登录失败并关闭连接

* 同一 `devId` 重复登录 = 重连，服务端会踢掉旧连接（见 "连接替换" 一节）

### 2.2 属性上报 310



```
{
  "msgType": 310,
  "devId": "BT000",
  "txnNo": 2,
  "attrList": [
    {"id": "01111001", "value": 5280},
    {"id": "01112001", "value": -125},
    {"id": "01113001", "value": 80},
    {"id": "01119001", "value": 28}
  ]
}
```

属性 ID 表（服务端只认这四个，其他 ID 忽略）：



| id       | 含义  | 原始单位   | 换算        | 范围       |
| -------- | --- | ------ | --------- | -------- |
| 01111001 | 电压  | 0.01 V | raw / 100 | ≥0       |
| 01112001 | 电流  | 0.01 A | raw / 100 | int32 范围 |
| 01113001 | SOC | %      | 原值        | 0–100    |
| 01119001 | 温度  | ℃      | 原值        | int32 范围 |

校验失败条件：



* `attrList` 不是数组或长度 >256

* 某项缺 `id` 或 `value`

* `value` 不是整数，或超出 int32

* 同一帧里重复上报同一个属性 ID

* 电压 < 0，或 SOC 不在 0–100

### 2.3 告警快照 410

**快照语义**：每次上报 "当前所有活动告警的完整列表"，服务端与内存里的上一帧做差分，自动算出新增 / 恢复。



```
{
  "msgType": 410,
  "devId": "BT000",
  "txnNo": 3,
  "alarmList": [
    {"id": "01003001", "alarmDesc": "03", "alarmFlag": 1}
  ]
}
```

规则：



* 只处理 `id == "01003001"` 的告警组，其他 id 忽略

* `alarmFlag`：1 = 活动，0 = 恢复

* `alarmDesc = "000"` 表示 "全部正常"，此时 `alarmFlag` 必须为 0

* `alarmDesc` 为 `"01"/"03"/"06"` 表示具体活动告警，此时 `alarmFlag` 必须为 1

* 不能同时出现 `"000"`（全部正常）和其他活动告警

* 同一帧内 `alarmDesc` 不能重复

* `alarmList` 长度 ≤256，单帧告警组 ≤64

典型序列（sim.cpp 里的演示）：



```
帧1: alarmList=[{"alarmDesc":"03","alarmFlag":1}]      → 03 告警产生
帧2: alarmList=[{"alarmDesc":"03","alarmFlag":1}]      → 03 仍在，刷新last时间
帧3: alarmList=[{"alarmDesc":"01","alarmFlag":1},
                {"alarmDesc":"03","alarmFlag":1}]       → 新增01，03仍在
帧4: alarmList=[{"alarmDesc":"01","alarmFlag":1}]       → 03恢复，01仍在
帧5: alarmList=[{"alarmDesc":"000","alarmFlag":0}]      → 01也恢复，全部正常
```

### 2.4 查询应答 911

终端收到服务端 910 后回：



```
{
  "msgType": 911,
  "devId": "BT000",
  "txnNo": 42,
  "attrList": [
    {"id": "8001", "protect": 4150, "recovery": 4100, "delay": 1000}
  ]
}
```



* `txnNo` 必须和 910 里的一致，否则服务端记一条 `orphan_response`

* `attrList` 内容由查询类型决定，示例里是 BMS 保护板参数

## 三、服务端 → 终端

### 3.1 统一应答格式

所有应答都是：



```
{
  "msgType": <对应应答类型>,
  "devId": "...",
  "txnNo": <请求的txnNo>,
  "result": 1
}
```

`result`：1 = 成功，0 = 失败。



| 应答  | 触发     |
| --- | ------ |
| 111 | 回复 110 |
| 311 | 回复 310 |
| 411 | 回复 410 |

失败应答示例（devType 不对）：



```
{"msgType": 111, "devId": "BT000", "txnNo": 3, "result": 0}
```

失败后服务端会发完这个包再关闭连接（`close_after_send=true`）。

### 3.2 下发查询 910



```
{"msgType": 910, "devId": "BT000", "txnNo": 42}
```



* `txnNo` 是服务端 SQLite 自增的查询任务 ID

* 3 秒内没收到 911，任务标为 `timeout`

* 超时后才到的 911 会被记为 `late_response`，不改变任务状态



***

## 四、连接生命周期

### 4.1 新连接登录前



* 连接 accept 后 5 秒内必须发 110 登录，否则服务端关闭（`login_timeout`）

* 登录前发非 110 报文，服务端回 `rejected: invalid_envelope`

* 登录前收到的帧会被缓冲（`held` 队列，最多 64 帧 / 256KB），登录成功后再处理

### 4.2 连接替换（relogin）

同一 `devId` 新连接登录成功后：



1. 服务端在一个 SQLite 事务里：更新设备登记 + 把旧连接的 pending 查询标为 `link_lost/reason=replaced`

2. 事务提交后才发 111 成功

3. 主线程关闭旧 fd，token 绑定从旧 token 切到新 token

4. 旧连接迟到的报文 / 关闭通知会被丢弃（`stale_events` / `unbound_device`）

### 4.3 服务端主动关闭的原因



| reason                      | 触发条件                 |
| --------------------------- | -------------------- |
| `login_timeout`             | accept 后 5 秒没登录      |
| `frame_timeout`             | 一个 JSON 对象超过 5 秒没收完整 |
| `send_timeout`              | 发送缓冲 5 秒没进展          |
| `consecutive_bad_json`      | 连续 3 帧 JSON 解析失败     |
| `held_overflow`             | 登录前缓冲超过 64 帧 / 256KB |
| `overloaded`                | worker 输入队列满         |
| `protocol_close`            | 协议层要求关闭（如非法登录）       |
| `replaced`                  | 被新连接挤掉               |
| `peer_eof`                  | 对端正常关闭（recv 返回 0）    |
| `recv_error` / `send_error` | 连接出错                 |
| `server_shutdown`           | 服务端退出                |

## 五、服务端日志事件（非网络报文，stdout 输出）

### 5.1 连接类



```
{"event":"accepted","connection_id":"<boot-uuid>:11","fd":23,"active_clients":5}
{"event":"closed","connection_id":"...","reason":"peer_eof","was_current":true}
{"event":"session_replaced","devId":"BT000","old_connection_id":"...","connection_id":"..."}
```

### 5.2 业务类



```
{"event":"login","devId":"BT000","state":"online_fresh"}
{"event":"attributes","devId":"BT000","voltage_v":52.80,"current_a":-1.25,"soc":80,"temperature_c":28}
{"event":"alarms","devId":"BT000","open":1,"history":1}
{"event":"device_state","devId":"BT000","state":"connected_stale",...}
```

### 5.3 查询类



```
{"event":"query_state","txnNo":42,"devId":"BT000","state":"pending"}
{"event":"query_state","txnNo":42,"devId":"BT000","state":"success",
 "response":{...911的attrList...}}
{"event":"query_state","txnNo":42,"devId":"BT000","state":"timeout","reason":"deadline"}
{"event":"late_response","txnNo":42,"devId":"BT000"}
{"event":"duplicate_response","txnNo":42}

```

### 5.4 拒绝 / 错误类



```
{"event":"rejected","reason":"invalid_login"}
{"event":"rejected","reason":"unbound_device"}
{"event":"bad_json","connection_id":"..."}
{"event":"storage_error","reason":"..."}
```

### 5.5 CLI 交互后看到的格式化输出（quiet 模式）



```
[STATUS] BT000 | online_fresh（在线，数据新鲜） | 电压=52.80V | 电流=-1.25A | SOC=80% | 温度=28C | worker=0

[RESULT #42] {"attrList":[...]}
[LATE #42] BT000 收到迟到应答，状态仍为timeout。
```

## 六、CLI 命令（stdin，非网络报文）

在服务端前台终端输入：



| 命令                       | 作用                     |
| ------------------------ | ---------------------- |
| `status BT000`           | 查单设备状态                 |
| `query BT000`            | 下发查询（触发 910）           |
| `task 42`                | 查某条查询任务的结果（从 SQLite 读） |
| `devices`                | 列所有设备                  |
| `alarms BT000`           | 列某设备告警历史（最近 100 条）     |
| `stats`                  | 队列 / 在线 / 拒绝统计         |
| `quiet on` / `quiet off` | 切换安静模式                 |
| `help`                   | 帮助                     |
| `quit`                   | 优雅退出                   |



***

## 七、设备状态机



```
connected_unauthed  ──110成功──►  online_fresh
                                    │
                          90秒没新数据  ▼
                                connected_stale
                                    │
                              断开  ▼
                                  offline
                                    │
                              重新登录 ▼
                                online_fresh
```

只有 `online_fresh` 状态才能下发查询，其他状态 `query` 会直接返回 `link_lost` 不发 910。
