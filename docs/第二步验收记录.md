# 第二步验收记录（M2）

日期：2026-10-19。对应第一版方案B01—B05，当前版本0.2.0。原A阶段回归测试继续保留，本轮不包含工作线程、查询和SQLite。

## 实现变化

- 多连接epoll LT服务，默认128条连接上限；每次accept的新token独立于fd，日志标识为boot_id:token。
- 新增session.hpp，设备档案和当前连接分开；合法登录才绑定/替换，旧会话消息与关闭通知无权修改当前设备。
- 连接替换或断开重连，保留当前进程内的告警记录；属性重新采集。同连接重复登录不清空数据。
- 周期检测并输出设备状态变化，默认新鲜度90秒；测试参数明确标注，默认值未改变。
- C++模拟器默认32条连接，先全部连接再逐设备演示；增加可重复的relogin演示。
- 内存设备档案上限1024、每设备历史上限4096；没有无限保存任意新设备档案。

## 边界

1. 目前业务仍在单个epoll线程处理；没有工作线程或线程池性能结论。
2. 模拟器32条连接同时存在，但其业务演示逐设备进行；并行发送验证来自独立Python客户端。未宣称最大并发或吞吐。
3. 设备档案/告警跨连接保留只在当前进程有效，重启全部丢失；111/311/411都不代表数据库提交。
4. fd复用的实际发生由网络测试检查，旧令牌业务隔离由会话单测和替换集成测试共同验证，不声称已穷举所有内核事件排列。
5. 没有企业平台、真实电池或现场长期运行证据。C/D/F阶段仍待完成。
