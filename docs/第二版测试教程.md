## 2. 两个终端启动真实HTTP接口

如果旧服务占着19001，先在旧A/B窗口停止它和模拟器。终端A：

```sh
cd /home/book/batt-access-v2
./build/batt-access --db access-v2.db --http-port 19002 --quiet
```

ready包含version=2.0.0及http_port=19002。不写--http-port时不启动HTTP。终端B：

```sh
cd /home/book/batt-access-v2
./build/batt-sim --demo serve --devices 1
```

B出现serving后，A仍可输入status BT000、query BT000、task编号、stats等原命令。设备与HTTP入口共用同一组worker和任务状态。

## 3. 在第三个Linux终端调用HTTP

以下是shell命令，不要输入A的服务CLI。使用已安装的curl：

```sh
curl -i http://127.0.0.1:19002/v1/devices/BT000
curl -i -H 'Content-Type: application/json' --data '{"devId":"BT000","clientRequestId":"manual-001"}' http://127.0.0.1:19002/v1/queries
```

首次应为201，带Location及txnNo。201仅说明任务落库，state可能仍pending；不等待设备查询完成。用实际编号（例如101）：

```sh
curl -i http://127.0.0.1:19002/v1/queries/101
curl -i -H 'Content-Type: application/json' --data '{"devId":"BT000","clientRequestId":"manual-001"}' http://127.0.0.1:19002/v1/queries
curl -i 'http://127.0.0.1:19002/v1/alarms?devId=BT000&status=open&limit=1'
```

第二次POST应200、replayed=true、txnNo与首次相同，即使原任务已成功，也不再发910。不同请求号表示新的查询；同设备已有pending时返回409 busy。HTTP等待超时返回503/unknown或连接断开时，保留原请求号重试。

把同一manual-001改为另一个devId再POST，会返回409 request_id_conflict，原任务不变。如果先前没有使用该请求号、设备不存在，则返回404。已登记但offline的设备会创建link_lost终态任务并返回201，这是沿用V1的规则。

告警按全局id倒序；有下一页时nextBeforeId给出游标，下一次URL加beforeId=该数字。最后一页为null。每页默认20，最大50；新告警不会使旧id重复到下一页，但不同页之间告警状态仍可能变化。

## 4. 从Windows通过SSH隧道访问

保持A/B运行。在Windows PowerShell中启动隧道（使用平时SSH的认证方式）：

```powershell
ssh -p 2222 -N -L 127.0.0.1:19002:127.0.0.1:19002 book@127.0.0.1
```

该窗口保持运行，另开一个Windows PowerShell：

```powershell
Invoke-RestMethod http://127.0.0.1:19002/v1/devices/BT000
$body = @{devId='BT000'; clientRequestId='windows-001'} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:19002/v1/queries -ContentType application/json -Body $body
```

链路是Windows本机19002→SSH2222→Ubuntu本机19002，不需要新增VirtualBox的HTTP端口映射。若Windows19002已占用，可将-L最前面的端口改成29002，访问URL也改为29002。也可使用MobaXterm的SSH本地端口转发功能。结束时在隧道窗口Ctrl+C。

```sh
BATT_BUILD_DIR=build-asan BATT_SANITIZE=ON sh scripts/test-linux.sh
```

schema2保留设备、告警和旧查询，增加可空client_request_id及索引；CLI历史为NULL。升级旧库必须先备份并在副本验证；V1不能直接读取schema2。本轮使用新库，不要求你迁移旧手动库。

## 6. 读第二版新增代码

沿一次POST阅读：http_api.cpp解析/校验→ApiBridge::call创建上下文→access.cpp的drain_api路由→worker.cpp共用command处理→Queries::prepare→Store::create_api_query事务→仅created发布缓存与910→ApiContext完成结构化结果→HTTP201。

然后分别跟踪：同号重放为何在busy之前命中；HTTP超时后的晚到结果为何不访问旧Response；不同分片同时使用一个请求号如何冲突；停止时为何先关闭入口/唤醒等待者，再回收线程。每个问题都有api_test/http_test对应证据。

HTTP库是阻塞I/O，由库固定2个线程处理；设备网络仍用epoll。没有自研通用线程池、HTTP Reactor、公网鉴权或设备写控制功能。
